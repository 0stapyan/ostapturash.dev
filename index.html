Distributed Booking System

C# / .NET, RabbitMQ, Kafka, PostgreSQL, Kubernetes. Team of three.

  • A hotel-booking platform of ~10 microservices, each with its own database, deployed to GKE with Helm and per-service CI/CD.
  • Bookings run as an orchestrated saga with the outbox pattern and compensating actions, with no two-phase commit.
  • Change Data Capture (Debezium → Kafka) feeds local read replicas, so bookings keep working when upstream services are down.
  • Resilience checked with chaos experiments, Pact contract tests, k6 load tests and canary releases.

How one booking moves through the saga

  1. place-bookingBookingService starts the saga
  2. reserve-roomon failure: release-room
  3. charge-paymenton failure: refund-payment
  4. confirm-bookingPivot: after this, steps only retry
  5. send-confirmationRetried until delivered
